# rc.35 定制兼容升级与部署

## 版本及保留范围

目标上游固定为官方 `v1.0.0-rc.35`（`bee45b58a3c0b77e8dc81e6b5aeb4474aa9058d1`），定制版本标识为 `v1.0.0-rc.35.custom.1`。升级从 fork/main `fe0cd4aa2` 出发，不以旧视频功能分支作为升级来源。

保留契约：

| 定制 | 保留要求 |
| --- | --- |
| Responses | `/responses` 与 `/v1/responses` 入口、DeepSeek 原生转发、各渠道兼容转换、工具往返与流式用量处理 |
| 耗时颜色 | 首字 10/30/60 秒，总耗时 60/180/300 秒，绿黄橙红；文字/竖条/详情一致 |
| API 地址 | 用户界面地址展示与复制 |
| 定价编辑 | 管理员输出倍率优先于内置默认值，允许显式零值，不重新锁定价格 |
| 保存反馈 | 避免一次设置操作出现重复成功通知 |
| 部署 | 保留原 Compose 域名白名单、loopback 端口、数据库/Redis 配置与数据卷 |

视频任务插件、时长/分辨率计费与模型支持使用官方 rc.35 实现。旧视频定制不回补；不承诺旧视频价格配置自动适配新机制。

## 升级风险

官方 rc.35 发布说明仍将插件系统标为实验性、不推荐直接用于生产；从 rc.26 或更早版本升级须重新配置所有视频模型价格。当前 fork 的版本字符串曾包含 rc.33，但实际上游基线更早，不能据此跳过迁移和价格检查。

数据库依赖使用上游配套版本：GORM v1.25.12、MySQL driver v1.5.7、PostgreSQL driver v1.5.9、glebarez/sqlite v1.11.0。已读取这些驱动的 go.mod，其声明的 GORM 版本分别为 v1.25.7、v1.25.10、v1.25.7；该检查只确认依赖关系，不能替代真实三数据库测试。

## 服务器上线前

1. 安排维护窗口、停止新任务/写入；等待重要在途视频任务完成，避免跨版本结算不一致。
2. 记录当前 Git 提交、容器镜像 ID；为原镜像保留独立 Tag，不要在确认升级成功前清理镜像。
3. 备份主数据库和配置；若使用独立日志库，单独备份。当前项目 Compose 使用 PostgreSQL，备份应由具备权限的运维人员执行 pg_dump，并验证备份可恢复。
4. 安全保存 `.env`、自定义插件及其他挂载配置。不要将备份或真实凭据加入 Git、日志或 Docker 构建上下文。
5. 保留已有 `postgres_data`、`redis_data` 及 bind mount；禁止 `docker compose down -v`、volume prune 或删除数据目录。

## 拉取、构建、启动

在本次升级已推送且运维完成上述备份后，服务器仍在 main、无本地未提交改动时：

```sh
cd /opt/forknewapi
git status --short
git pull --ff-only origin main
docker compose build new-api
docker compose up -d --no-deps new-api
docker compose ps new-api
docker compose logs --tail=100 new-api
```

保留项目原有 PostgreSQL/Redis 服务，不主动重建它们。Compose 服务名沿用仓库的 `new-api`。日志检查仅在服务器本地进行，不公开可能包含的业务数据。单纯 restart 不会切换新镜像。

## 上线验收与回滚

- 检查登录、旧用户余额/API Key/渠道/消费记录是否保留。
- 检查实际使用的 Responses 模型：普通输出、流式工具调用、工具结果回传、计费日志。
- 检查首字与总耗时边界颜色；设置保存、API 地址复制等定制仍可使用。
- 重新核对视频插件开关与模型价格，再进行受控的小额真实视频验收；逐项核对预扣、实际时长、成功结算及失败退款，不因本地模拟测试通过就默认真实供应商契约成立。
- 若需要回滚：停止新版本写入，恢复升级前数据库备份、配套旧镜像和配置；避免让旧程序直接运行于已改变且未经逆向验证的 schema。
